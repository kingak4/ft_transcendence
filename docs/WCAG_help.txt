==========================================================================================
AUTOMATED WCAG 2.1 AA SCAN (axe-core + Playwright) - /root/a11y-audit
==========================================================================================

Lives OUTSIDE the repo on purpose: nothing here shows up in the git diff.

Files in /root/a11y-audit:
  audit.mjs            the scanner (tags: wcag2a, wcag2aa, wcag21a, wcag21aa)
  routes.public.json   pages scanned logged-out
  routes.app.json      pages scanned logged-in  (contains USER IDs -> see step 3)
  auth.json            saved login session of user A (created in step 4)
  report-<set>-<theme>.json   full results of the last run (overwritten each run)

Environment variables audit.mjs understands:
  BASE_URL   default https://localhost:8443
  ROUTES     default routes.public.json
  AUTH       path to a session file; unset = logged-out visitor
  THEME      brand | mocha | latte   (default brand)


------------------------------------------------------------------------------------------
WHEN TO REDO THE SETUP
------------------------------------------------------------------------------------------
A full Docker rebuild (containers + volumes) wipes the database, so:
  - users A and B no longer exist   -> redo step 2
  - their IDs change                -> redo step 3 (routes.app.json)
  - auth.json points at a dead session -> redo step 4
Symptoms in the scan output:
  "(redirected to /login!)"  -> session expired/invalid  -> step 4
  profile / chat route shows unexpected results or 404  -> IDs changed -> steps 2-3
Step 1 is needed only once per machine.


------------------------------------------------------------------------------------------
STEP 1 - install the tools (once)
------------------------------------------------------------------------------------------
  cd /root/a11y-audit && npm init -y && npm i playwright @axe-core/playwright && npx playwright install --with-deps chromium

  npm init -y              creates package.json (does not touch existing files)
  npm i ...                installs Playwright + the axe integration
  playwright install ...   downloads headless Chromium + the Linux libraries it needs


------------------------------------------------------------------------------------------
STEP 2 - test data: two users and a conversation (in Windows Chrome)
------------------------------------------------------------------------------------------
Why two users: the conversation page only shows message bubbles, timestamps and
the "Online" label when there is a real chat with real messages. Without them
axe never sees (and never checks) those elements.

  1. Normal Chrome window:    https://localhost:8443/register  -> register user A
  2. Incognito window (Ctrl+Shift+N): /register              -> register user B
     (separate windows = separate cookies = both logged in at the same time)
  3. As A: Friends page -> search for B -> Add friend
  4. As A: open the chat with B, send 2-3 messages
  5. As B: reply with 2-3 messages    (so both bubble styles exist: mine / theirs)
  6. As A: delete ONE of A's messages (hover or Tab to it -> trash icon)
     (so the "(message deleted)" style gets checked too)
  7. Keep B's incognito window OPEN while scanning -> B shows as "Online",
     so the online label gets checked as well.

User A = the scanner's user. User B only exists to be chatted with.


------------------------------------------------------------------------------------------
STEP 3 - put the new IDs into routes.app.json
------------------------------------------------------------------------------------------
  - A's user ID:  as A, open your profile -> copy the last part of the URL
                  https://localhost:8443/<A_ID>
  - Chat URL:     as A, open the chat with B -> copy the path from the address bar
                  /chat?friend=<B_ID>

Edit /root/a11y-audit/routes.app.json so it looks like this:

  [
    "/chat",
    "/chat?friend=<B_ID>",
    "/friends",
    "/<A_ID>"
  ]

DO NOT add /auth/logout - it is a route handler that logs you out, and every
page after it would silently be scanned as /login.


------------------------------------------------------------------------------------------
STEP 4 - save A's login session
------------------------------------------------------------------------------------------
  cd /root/a11y-audit && npx playwright codegen --ignore-https-errors --save-storage=auth.json https://localhost:8443/login

A browser window opens (WSLg). Log in as A, then CLOSE the window.
The session cookies are written to auth.json. Ignore the code-recorder panel.


------------------------------------------------------------------------------------------
STEP 5 - run the full scan (both page sets x all 3 themes = 6 runs)
------------------------------------------------------------------------------------------
  cd /root/a11y-audit && for t in brand mocha latte; do THEME=$t node audit.mjs; ROUTES=routes.app.json AUTH=auth.json THEME=$t node audit.mjs; done 2>&1

  for t in brand mocha latte; do ...; done   repeat for each theme, $t = theme name
  THEME=$t node audit.mjs                     public pages, logged out
  ROUTES=... AUTH=... THEME=$t node ...       app pages, logged in as A
  2>&1                                        show errors together with normal output

Same scan, but print only the headers and the pages that FAIL (quiet when clean):

  cd /root/a11y-audit && for t in brand mocha latte; do THEME=$t node audit.mjs; ROUTES=routes.app.json AUTH=auth.json THEME=$t node audit.mjs; done 2>&1 | grep -v ': 0 failing' | grep -v '^$'

  grep -v PATTERN   = drop lines that match PATTERN
  '^$'              = an empty line

Goal: every page "0 failing rule(s)" in every theme.


------------------------------------------------------------------------------------------
STEP 6 - when something fails: which element, which colours
------------------------------------------------------------------------------------------
The summary only gives counts. This reads the saved reports (no new scan) and
prints one line per failing element:

  cd /root/a11y-audit && node -e '
  for (const f of process.argv.slice(1))
    for (const r of require("./" + f))
      for (const v of r.violations)
        for (const n of v.nodes) {
          const d = n.any[0]?.data ?? {};
          console.log([f, r.route, v.id, n.target.join(" "), d.fgColor, d.bgColor, d.contrastRatio + "/" + d.expectedContrastRatio, d.fontSize, n.html.slice(0, 160)].join(" | "));
        }
  ' report-*.json

Columns: report file | route | rule | CSS selector | text colour | background |
         actual/required ratio | font size | start of the HTML
(colour columns are empty for non-contrast rules - that is normal)

Contrast thresholds (WCAG 1.4.3 / 1.4.11):
  normal text ................................ 4.5 : 1
  large text (>= 24px, or >= 18.66px bold) ... 3   : 1
  UI parts: borders, icons, focus rings ...... 3   : 1
  disabled controls .......................... exempt

STEP 7 - static lint of the source
------------------------------------------------------------------------------------------
  cd /root/ft_transcendence/frontend && npx eslint app 2>&1 | tail -60

Silence = clean.


------------------------------------------------------------------------------------------
WHAT THE AUTOMATED SCAN CANNOT SEE
------------------------------------------------------------------------------------------
It checks each page as it LOADS. It does not open dialogs, menus or search
dropdowns, and does not type or press keys. Check these by hand with the axe
DevTools / WAVE extensions in Windows Chrome:
  - Edit avatar / Edit display name dialogs (open them first, then scan)
  - chat-sidebar user search with results showing
  - ConnectionBanner while visible (stop the backend container to trigger it)

Automated tools catch only ~30-40% of WCAG problems. Manual checklist:
  Keyboard only ...... Tab / Shift+Tab / Enter / Space / Esc through every page
                       and dialog; focus always visible; never trapped
  NVDA ............... headings (H), landmarks (D), forms; new chat message
                       is announced "New message from B: ..."
  Zoom ............... 200% browser zoom, and a 320px-wide window:
                       no horizontal scrolling, no clipped text
  All 3 themes ....... switch in the footer, repeat the visual checks


==========================================================================================
NVDA SCENARIO - step by step (Windows Chrome, https://localhost:8443)
==========================================================================================

Before you start
  1. Steps 2-4 of the scan setup are done (users A and B, a chat with messages).
  2. Start NVDA (Ctrl+Alt+N), then open NVDA menu (Insert+N) -> Tools -> Speech Viewer.
  3. Before each section: right-click in Speech Viewer -> clear, or just note
     where the section starts. After each section copy the Speech Viewer text
     and paste it to Claude with the section number.

The "Expect" lines are approximate - NVDA's exact wording varies by version.
What matters is that the MEANING is there (name, role, state).
A section FAILS if NVDA says nothing, says only "button"/"edit"/"clickable"
with no name, reads something visually hidden by mistake, or focus jumps
somewhere unexpected (e.g. to the top of the page).

Browse mode vs focus mode
  Browse mode  = reading the page; single letters jump (H, D, F, K ...)
  Focus mode   = typing into a field; letters type text
  NVDA switches automatically when you Tab into a field. Insert+Space toggles.
  Esc in a text field leaves focus mode first - in section 4 you may need to
  press Esc twice (once for NVDA, once for the app).


------------------------------------------------------------------------------------------
SECTION 1 - Login page, logged out (/login)
------------------------------------------------------------------------------------------
  Action                              Expect
  Load the page                       "Login · 42Hub"
  Tab                                 "Skip to main content, link" (link appears top-left)
  Enter, then Tab                     focus lands on the first form field, not the logo
  Insert+F7 -> Landmarks              banner, main, content info (footer)
  H                                   "heading level 1, Login"
  F (next form field)                 a field with a NAME, e.g. "Email, edit"
                                      (just "edit" with no name = FAIL, report it)
  F                                   "Password, edit, protected"
  Tab to Login button, Enter          (empty form) the error messages are read,
                                      and focus moves to the first invalid field

------------------------------------------------------------------------------------------

  X (next checkbox)                   "I agree to the Terms of Service and Privacy
                                      Policy, check box, not checked"
  Space                               "checked"
  K (next link) x2                    "Terms of Service, link", "Privacy Policy, link"

                                      section heading "1. Introduction" ...
  Tab                                 "Skip to main content, link"
  Tab                                 "main landmark" (the scrollable area got focus)

SECTION 4 - Own profile, logged in as A (/<A_ID>)
------------------------------------------------------------------------------------------
  Load the page                       "My Profile · 42Hub"
  Insert+F7 -> Landmarks              "Sidebar" complementary, "Main" navigation,

  Esc                                 dialog closes; "Edit avatar, button"
  Tab to "Change name", Enter         "Display name, edit, <your name>"

  Esc (x2, see note above)            "Change name, button"

------------------------------------------------------------------------------------------
  Load the page                       "Friends · 42Hub"
  H                                   "heading level 1, Friends"

------------------------------------------------------------------------------------------
SECTION 6 - Chat (/chat?friend=<B_ID>)  - keep B's incognito window open
------------------------------------------------------------------------------------------
  Load the page                       "Chat · 42Hub"
  D repeatedly                        ... "Chats, complementary", "Chats, navigation",
                                      "Messages, region" ...
  In the Chats list (K / Tab)         B's row: "<B name>, link, current page"
  Inside "Messages" (Down arrow)      every bubble starts with its sender:
                                      "You: ..." / "<B name>: ..."
                                      deleted one: "You: (message deleted)"
  Tab onto one of YOUR messages       "Delete message, button" - and the trash icon
                                      becomes VISIBLE on screen
  Tab to the message field            "Message, edit"
  Stay in the field. In B's window,
  send "hello from B"                 A's NVDA says "New message from <B>: hello
                                      from B" WITHOUT focus moving
  Send a message yourself (Enter)     your own message is NOT announced (by design)

  Optional - connection error:
  Stop the backend container, then
  type and send a message             "Failed to send message: Not connected to
                                      server" is read out (alert)


------------------------------------------------------------------------------------------
SECTION 7 - Mobile navigation drawer (any logged-in page)
------------------------------------------------------------------------------------------
  Make the Chrome window narrow (< 1024 px) until the hamburger appears.
  Tab to it                           "Open navigation, button, collapsed"
  Enter                               focus moves to the first link in the drawer
                                      (e.g. "42Hub, link" or "My Profile, link")
  Esc                                 drawer closes; "Open navigation, button, collapsed"
  KNOWN LIMITATION: while the drawer is open, Tab can still reach the page
  behind it (the drawer is not modal). Not a WCAG failure; note it, don't report.

------------------------------------------------------------------------------------------
  Tab to the theme buttons            "Theme, grouping"; "42Hub, toggle button,

  Space on "Mocha"                    "pressed"; the page switches to the dark theme
